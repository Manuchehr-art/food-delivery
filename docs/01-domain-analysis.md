# Анализ предметной области: ИС «Доставка еды» (food-delivery)

## 1. Организация

Сеть ресторанов быстрого питания «Вкусно и быстро» (далее — сеть) из 12 точек в городе.
Клиенты заказывают блюда через колл-центр по телефону и через Telegram-бота; операторы
принимают заказы в Excel-таблице, передают список поварам на бумаге, а курьерам —
в мессенджере. Оплата — наличными курьеру или переводом на карту оператора.
Среднее время обработки заказа — 15 минут только на приём, ещё 30–50 минут — готовка
и доставка. В час пик (12:00–14:00, 19:00–21:00) теряется до 20 % звонков.

### Проблемы текущего процесса
- заказ теряется между оператором, поваром и курьером — нет единого журнала;
- клиент не может отследить статус заказа («готовится / выехал / доставлен»);
- нет учёта популярности блюд — меню не обновляется по спросу.

## 2. Акторы

| Роль в системе | Кто это | Что делает в системе |
|---|---|---|
| admin | администратор ИТ-отдела сети | ведёт справочники ресторанов, блюд, зон доставки, пользователей |
| manager | оператор / менеджер ресторана | принимает и подтверждает заказы, назначает курьера, видит отчёты |
| courier | курьер | видит назначенные заказы, меняет статус «в пути / доставлен» |
| client | клиент (физлицо) | регистрируется, выбирает блюда, оформляет и оплачивает заказ, оставляет отзыв |

## 3. Бизнес-процессы

| Процесс | Участники | Результат |
|---|---|---|
| Регистрация клиента | client | учётная запись + адрес(а) доставки |
| Оформление заказа | client, система | заказ со статусом new |
| Обработка и доставка заказа | manager, courier, client | заказ доставлен, статус delivered, оплата проведена |
| Отмена заказа | client, manager | заказ со статусом cancelled, возврат средств (если оплачен) |
| Добавление блюда в меню | manager, admin | новая карточка блюда в справочнике ресторана |
| Формирование отчёта за смену | manager, admin | отчёт по выручке, количеству заказов и популярным блюдам |

### 3.1. Обработка и доставка заказа (подробно)

1. Клиент выбирает ресторан и добавляет блюда в корзину; указывает адрес и способ оплаты.
2. Система проверяет, что адрес входит в зону доставки ресторана, и что сумма ≥ минимальной.
3. Заказ получает статус `new` и появляется в списке оператора.
4. Оператор (manager) подтверждает заказ — статус меняется на `accepted`, уведомление уходит на кухню.
5. После готовности еды оператор назначает свободного курьера — статус `preparing`, затем `cooking`.
6. Курьер забирает заказ и нажимает «В пути» — статус `on_the_way`, клиент получает ссылку на отслеживание.
7. Курьер доставляет заказ, получает оплату и нажимает «Доставлен» — статус `delivered`, заказ закрывается.
8. Клиент может оставить отзыв и оценку (1–5 звёзд), которые сохраняются в карточке заказа.

## 4. Объекты данных

| Объект | Основные сведения |
|---|---|
| Клиент | ФИО, телефон, e-mail, пароль (хеш), список адресов, дата регистрации |
| Ресторан | название, адрес, телефон, часы работы, список зон доставки, рейтинг |
| Блюдо | название, описание, цена, категория, фото, доступность (в наличии / нет), ресторан |
| Заказ | номер, клиент, ресторан, адрес доставки, сумма, способ оплаты, статус, дата создания, дата доставки |
| Позиция заказа | блюдо, количество, цена на момент заказа, сумма по позиции |
| Курьер | ФИО, телефон, транспорт (пеший / авто / вело), текущий статус (свободен / занят), рейтинг |
| Адрес доставки | улица, дом, квартира, подъезд, этаж, комментарий, координаты (lat/lon) |
| Отзыв | заказ, клиент, оценка (1–5), текст, дата |

## 5. Глоссарий

| Термин | Определение |
|---|---|
| Заказ | оформленная клиентом корзина блюд с адресом и способом оплаты; имеет жизненный цикл статусов |
| Позиция заказа | строка заказа: одно блюдо в указанном количестве |
| Зона доставки | геометрическая область вокруг ресторана, в которой работает доставка |
| Минимальная сумма заказа | порог стоимости корзины, ниже которого заказ не принимается |
| Статус заказа | одно из состояний жизненного цикла: new, accepted, cooking, on_the_way, delivered, cancelled |
| Время доставки | расчётный интервал от подтверждения заказа до вручения клиенту |
| Чаевые | добровольная доплата курьеру, добавляемая клиентом при оформлении |
| Рейтинг курьера | среднее арифметическое оценок клиентов за последние 30 дней |
| Карточка блюда | запись в справочнике меню: название, цена, фото, описание, доступность |
| Свободный курьер | курьер, у которого нет активных заказов со статусом on_the_way |

## 6. Источники требований

- **Интервью** с менеджером службы доставки (вымышленное, 30 мин):
  1. Сколько заказов обрабатывает сеть в день?
  2. Как сейчас принимается заказ от клиента?
  3. Кто и как передаёт заказ на кухню?
  4. Как выбирается курьер для заказа?
  5. Какие статусы проходит заказ в течение дня?
  6. Как клиент узнаёт, что заказ готов / выехал?
  7. Что происходит при отмене заказа после оплаты?
  8. Какие отчёты нужны руководству в конце смены?
  9. Как считается минимальная сумма и зона доставки?
  10. Какие проблемы в процессе вы хотите решить в первую очередь?
- **Анализ аналогов**: изучены интерфейсы и сценарии Яндекс.Еда, Wolt, Delivery Club —
  выделены общие сущности (заказ, позиция, курьер) и типовые статусы заказа.
